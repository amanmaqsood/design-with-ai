# Interface review

Use this review for critique mode. Inspect the supplied artifact directly when possible and distinguish observed evidence from inference.

## Review order

1. Reconstruct the intended user, job, primary action, and critical path.
2. Identify the screen's apparent information hierarchy before judging its styling.
3. Find conflicts between that hierarchy and the product constraints.
4. Trace local problems back to their shared cause: information model, workflow, component API, content, or visual system.
5. Recommend the smallest systemic change that resolves the largest group of problems.

## Checks

- **Comprehension**: Can a new user tell what this is, what changed, and what to do next?
- **Priority**: Does visual emphasis match task importance and frequency?
- **Flow**: Are prerequisites, consequences, exits, and recovery paths visible at the right moment?
- **Density**: Is related information grouped without turning every group into a card?
- **Language**: Is copy specific, concise, and necessary? Do labels describe outcomes rather than implementation?
- **Consistency**: Do repeated meanings use repeated components, positions, and terms?
- **States**: Do non-ideal states preserve context and suggest a safe next action?
- **Accessibility**: Can the flow be perceived and operated without relying on color, precision pointing, or animation?
- **Authenticity**: Does the interface express this product's real model, or could it belong to almost any AI-generated app?

## Finding format

Rank findings by user impact, not visual annoyance. For each material finding provide:

- observed evidence;
- user consequence;
- systemic cause;
- recommended change;
- how to validate the change.

Do not invent research findings, user behavior, or technical limitations. If evidence is missing, name the uncertainty and propose the cheapest discriminating test.
